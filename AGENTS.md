## Commands

Run from `web/` unless stated.

| Task | Command |
|---|---|
| Install | `npm ci` |
| Dev server | `npm run dev` |
| Type-check | `npm run typecheck` |
| Tests | `npm run test` |
| Production build | `npm run build` (type-checks first; output `web/dist/`, git-ignored) |
| Results | `npm run eval` (writes `eval/results.md`, `eval/results.json`, `web/public/layouts/sa_seed42.json`) |
| README generated blocks | `npx tsx ../scripts/sync-readme.ts` (add `--check` to fail if stale) |
| Floor-plan diagram | `npx tsx ../scripts/floorplan.ts` |
| Pitch deck | in `docs/pitch/deck/`: `npm ci`, then `npm run build` (`npm run build -- --strict` exits 1 if anything is still pending) |
| Data (rarely) | from the repo root: `python data/prepare.py <online_retail_II.xlsx> web/public/data/orders.json --month 2011-11 --top 100` |

Before every push that touches code: `npm run typecheck && npm run test`. After any change under `web/src/sim/` or `eval/`: run `npm run eval`, commit the results, then re-run the README sync and the deck build.

## Rules

1. **Commit small, commit often, push promptly.** The rules require at least hourly commits, and only pushed commits count. Push your branch as soon as you commit; don't sit on local commits.
2. **No trailers.** Never add `Co-Authored-By:` or any other trailer to commit messages. Commits are authored with the human's git identity. Declare AI assistance in the README and DEV_LOG instead.
3. **Commit message style:** `<Area>: <what changed> (#issue)`, for example `Engine: memoised simulate and planOrder (#1)` or `README: lead with the held-out result (#9)`.
4. **`main` is protected.** Force-pushes and deleting `main` are blocked for everyone, admins included. Direct pushes are allowed. Never rewrite pushed history: no `push --force`, no rebasing commits that are already pushed. For parallel work use a branch (`claude/<name>`, `review/<name>`), push it right away, and merge it into `main` with a normal merge or a PR.
5. **Numbers come only from `eval/results.md`.** Never type a result number by hand into code, README, deck, posts or Q&A. The README and deck pull their numbers through their generators. Hand-written texts (posts, demo script, Q&A cards) must match `eval/results.md`, and each such number is listed in the re-check table in `docs/pitch/README.md`. Fabricated results mean disqualification.
6. **Held-out stays held out.** Orders dated 16–30 Nov 2011 are scoring-only. The Baseline ranks by `picksTrain`, and simulated annealing scores train orders only. Never tune anything on held-out orders.
7. **The engine stays pure.** `web/src/sim/` imports nothing from React, the DOM or three.js, so the same code runs in the worker and in Node for `npm run eval`. No `Math.random()` or `Date.now()` in anything that affects a result: use `mulberry32(seed)`. The annealing budget is a number of iterations, never seconds.
8. **Contracts are extend-only.** In `sim/types.ts`, `worker/protocol.ts` and `store.ts`, add fields freely but never rename or remove an exported one. The scene only reads the store and calls the selection actions listed in `store.ts`.
9. **Keep it fast on a laptop.** Use instancing; stay within about 60 draw calls; no per-frame allocations or React state updates in `useFrame`; Bloom only at High quality.
10. **No secrets.** The app has no keys or backend. Never commit `.env` files or credentials; `.env.example` documents that nothing is needed.
11. **Data credit and privacy.** The dataset is UCI Online Retail II (Chen, 2019), CC BY 4.0, credited in the README. `prepare.py` never writes Customer ID or Country; keep it that way.
12. **Everyone must be able to explain everything.** Both team members may be asked about any file in Q&A. When you add or change behaviour, add a DEV_LOG entry with the decision and the reason, and keep `docs/architecture.md` accurate.
