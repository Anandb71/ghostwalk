## Network/access gotchas discovered tonight (affect several problems)
1. **UCI `archive.ics.uci.edu` is slow and truncates from here**: `online+retail+ii.zip` (43.5 MB per UCI page) died twice at 20.9 MB and 19.3 MB with HTTP 200 (chunked, no Content-Length, no Range support); a 20 s probe ran at 31 KB/s. **Use the HF/Kaggle mirrors below.** `fetch_ucirepo(id=502)` cannot work: UCI API returns `data_url: null` for 502 (VERIFIED). `fetch_ucirepo(id=601)` is fine (`data_url: https://archive.ics.uci.edu/static/public/601/data.csv`, VERIFIED).
2. **Kaggle anonymous download works with no token** (VERIFIED for 5 datasets): `curl -L "https://www.kaggle.com/api/v1/datasets/download/<owner>/<slug>[/<file>]"` → 302 to a signed GCS URL (valid 3 days), supports Range. Licence via `https://www.kaggle.com/api/v1/datasets/view/<owner>/<slug>` (`licenseName`).
3. **SINTEF (`sintef.no/projectweb/top/vrptw/...`) is behind a Cloudflare managed challenge**: 403 for curl (even with full browser headers), WebFetch, and the headless browser pane ("Just a moment…"). A human's normal browser will likely pass; scripts will not. Use the GitHub mirrors + Wayback copies below (all VERIFIED).
4. **`people.rit.edu` (MaintNet) serves an incomplete TLS chain**: plain `curl`/WebFetch fail ("unable to get local issuer certificate"); `curl -k` works; in Python use `requests.get(url, verify=False)` once, then commit the CSV to the repo (505 KB) — or use the Kaggle mirror.
5. **GitHub unauthenticated API quota (60/h) was exhausted mid-session; `gh` (authenticated as Anandb71, 5000/h) works** — prefer `gh api` for any tree/content listing.
6. **Git LFS**: `buildingsmart-community/Community-Sample-Test-Files` stores every `*.ifc` in LFS. `raw.githubusercontent.com` returns a 130-byte pointer file, NOT the model. Use `https://media.githubusercontent.com/media/<org>/<repo>/main/<path>` (VERIFIED 200, full bytes) or `GIT_LFS_SKIP_SMUDGE=0` clone.
7. **PlantDoc cannot be checked out on Windows/NTFS**: filenames contain `?`, `&`, `=` (e.g. `train/Cherry leaf/IMG_5892_original.JPG?1500348823.jpg`, `train/grape leaf/...picture-id183867740?k=6&m=...jpg`); even `git sparse-checkout` of one class aborts ("invalid path"/"Invalid argument", also with `core.protectNTFS=false`). Use WSL2/Linux/Colab, the GitHub ZIP via Python `zipfile` (renaming entries), or the HF mirrors.
8. **Hugging Face Spaces policy has changed (VERIFIED from current docs)**: "Static Spaces are free for everyone. Gradio and Docker Spaces run on compute and require a paid plan to create (PRO for personal accounts)". Free personal accounts *in good standing (verified email, account older than 30 days)* may host **up to 2 ZeroGPU Spaces** (Gradio SDK only, Python 3.10/3.12, Gradio ≥4; CPU-only code runs fine there; GPU only inside `@spaces.GPU`). Streamlit is no longer a listed SDK. **Do not plan on a free CPU-Basic Gradio/Streamlit Space unless someone on the team already has PRO or a ≥30-day-old account.**

## Can all compute run in the browser? (per problem)
- **Fully browser-capable, zero backend**: 2.1 (ONNX/JSON model), 2.3 (onnxruntime-web backbone + numpy-style prototypes), 3.1 (precomputed JSON), 3.2 (JS simulator over a sessions JSON), 3.3 (web-ifc WASM + rules JSON + three.js), 4.1, 4.2 (Three.js), 4.3 (JS heuristic solver), and the retrieval half of 1.3 (precomputed embeddings + BM25) and the SQL half of 1.2 (duckdb-wasm).
- **Needs a backend only for an LLM key**: 1.1, 1.2, 1.3 → one Vercel serverless function (Node) with `GROQ_API_KEY`/`GEMINI_API_KEY` in env; everything else static.
- **Needs real training compute before deploy**: 2.2 (and lightly 2.3) → Colab/Kaggle free GPU or laptop CPU, then ONNX export.

## Ranked shortlist: 5 most feasible in 17 h (data verified + free-tier-safe + demo-safe)
1. **4.2 Warehouse 3D twin** — data in hand (7 MB parquet → <1 MB JSON), zero external services, pure static deploy (Vercel/Cloudflare), no cold starts, no keys, no model training; the only risks are engineering polish and laptop GPU load, both controllable (instanced meshes, Web Worker replay). Highest visual ceiling of the feasible set.
2. **3.1 Safe outdoor hours** — single 16.7 MB file obtainable anonymously from Kaggle (verified), CC0, precompute everything offline → static site; practically zero deploy risk; technical depth comes from the reliability layer + back-test metric; lower wow unless the visualisation is excellent.
3. **2.3 Unknown-defect steel inspector** — 27 MB dataset from three independent open mirrors (figshare CC BY 4.0 verified), tiny 200×200 images make CPU-only feature extraction fast, open-set + 5-shot prototype logic is numpy/JS, and it can ship as a static ONNX app or a small FastAPI; must-haves are crisp and measurable (AUROC, confusion matrix with "unknown").
4. **1.2 Ask-your-data SQL agent** — same verified Retail II parquet; DuckDB (wasm or Python) is lightweight; deterministic trap-suite is cheap to build; only external dependency is a free-tier LLM (mitigate by caching suite results and keeping a fallback model). Skip the UCI zip entirely.
5. **3.3 BIM model checker** — models verified and downloaded (Duplex IFC2x3 2.4 MB with 14 doors/24 windows/21 spaces; IFC4 FZK-Haus 2.6 MB; small IFC4 Building-Architecture); ifcopenshell wheels install cleanly on Linux free tiers, and a web-ifc browser build removes upload/cold-start limits and makes the 3D-highlight stretch nearly free. Risks are schema/unit handling, not access.

Also trivially feasible but with a lower winning ceiling: **2.1** (0.5 MB, could be done in 3 h) and **4.1** (no data) — both score 5 on feasibility. **1.1** is a 5 on data but is LLM-key-dependent. **4.3** is a 4 (data tiny and verified via mirrors, best-known values recovered from Solomon's page; the dynamic re-planning logic is the time sink; OR-Tools fits Vercel-Python/Render or use a JS solver). **3.2** is a 4 pending ACN registration tonight (static mirror is a workable but laborious fallback). **2.2** is a 3 because of the 1 GB dataset, NTFS checkout failure, training time and the HF Spaces policy change.
